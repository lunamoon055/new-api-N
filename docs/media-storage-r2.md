# Cloudflare R2 媒体转存

系统设置 → 运维 → 媒体转存 → **添加 Cloudflare R2 图床**。此渠道直接从本站后端使用 R2 的 S3 API 上传，适用于生成图片、视频、音频及手动转存，和已有 HTTP 图床共用优先级、故障切换及视频重试队列。

## 配置

| 字段 | 填写内容 |
| --- | --- |
| R2 S3 API 端点 | 控制台显示的 `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`；带正确桶名的地址会自动去掉末尾桶名。地域限制桶使用控制台给出的对应端点。 |
| R2 存储桶名称 | 已创建的桶名，例如 `my-media-bucket` |
| 媒体公开访问地址 | 已绑定此桶的公开 HTTPS 域名，例如 `https://media.example.com` |
| 文件存储目录前缀 | 默认 `new-api/media`，可自定义或留空 |
| Access Key ID / Secret Access Key | R2 S3 API 凭证，具有该桶的对象读写权限，不是普通 Cloudflare API Token |
| 优先级 | 数值越小越先尝试；相同优先级保持配置顺序 |

新渠道默认关闭，可以先保存桶和域名，稍后填密钥。密钥保存后读取接口仅返回 `********`；保留该值可沿用原密钥。修改图床 ID 后不能复用旧 ID 的遮罩密钥，需要重新填写。

填写凭证后，先保持关闭并保存，再点 **测试上传**。测试写入一张极小的 PNG，随后不带 S3 凭证读取公开地址；上传权限和公开域名都通过后才显示成功。测试文件保留在配置前缀下，相同测试内容复用同一对象。确认成功后启用并保存。若希望优先使用 R2，把其优先级设为小于已有渠道的值。

R2 默认私有，S3 API 地址不能当作公开媒体链接。本功能不会自动修改 Cloudflare 的桶权限或域名配置；应使用已配置的公开域名。生产环境使用自定义域名，`r2.dev` 仅适合开发测试。参见 [Cloudflare 公开桶文档](https://developers.cloudflare.com/r2/buckets/public-buckets/)和 [S3 API 兼容说明](https://developers.cloudflare.com/r2/api/s3/api/)。

## 上传和兼容

- 使用 AWS SDK 的 SigV4 签名，服务 `s3`、区域 `auto`，发送 `PUT /<bucket>/<key>`，保持原始 Content-Type；不设置 ACL、不创建桶。
- 使用内容 SHA-256 和扩展名生成对象 key。同一内容/扩展名在同一前缀内复用 key，视频重试不会堆积随机命名的副本。不要在该前缀下手工存放需要独立修改的同名对象。
- 沿用当前 200 MiB 单文件上限。视频从缓存文件计算哈希并流式上传，不把整个视频再装入 multipart 内存缓冲。后台视频转存仍校验公开链接后才完成。
- 上传沿用现有 SSRF 防护，不跟随签名请求的重定向；错误不回显上游响应正文或密钥。普通 HTTP 图床继续使用原来的 multipart 协议。历史配置未提供 `type` 时按 `http` 处理。
- 设置仍保存在 `MediaStorageProviders` 配置项，无数据库结构迁移。必须先部署含 R2 支持的后端和前端，再保存或启用 R2；旧版本不识别这个类型。需要回退旧程序时，先移除 R2 配置并保存，保留 HTTP 渠道。

本地测试覆盖字节上传、视频缓存文件上传、签名字段、URL 转义、重复上传 key、错误脱敏、拒绝重定向、SSRF、公开地址验证及密钥遮罩/保留。测试通过不代表实际桶的凭证和公开访问已验证，最终以管理员页面的真实测试结果为准。
