# 一键兑换积分

卡网独立收款并发货，不提供本站可用的接口或支付回调。本站无法获知用户是否付款，也不会在用户返回钱包时自动到账。

## 六档购买入口与返回兑换窗口

1. 进入本站左侧“钱包”，在“添加资金”区域选择 **10、20、50、100、200、其他** 六档之一；每档点击后直接在新标签页打开各自的购买链接。原本站页面保留，并准备好兑换窗口。
2. 用户在卡网自行完成付款，并查看卡网的订单与发货内容。本站的“订单历史”不查询卡网订单。
3. 买完切回本站即可看到兑换窗口：核对当前账号、粘贴卡网发货的兑换码，再点击“兑换积分”。窗口内显示所选档位，但实际到账额度只取服务端兑换码额度。弹窗只由购买操作唤起，不代表已经付款。
4. 原页面刷新、关闭后重新打开本站，登录账号相同时仍可恢复待兑换窗口（待兑换提示最长保留 24 小时）；点击“稍后兑换”、关闭弹窗或完成后点击“完成”会清除提示。同一浏览器的其他本站标签页也能恢复提示。“我已购买，去兑换”可以随时手动打开窗口。
5. 若发货内容仍是兑换链接，打开该链接继续沿用原先的识别与确认流程；初始化成功后会清除购买返回提示，避免弹出两个窗口。原钱包输入框的手动兑换同样保留。

返回动作由用户打开链接或切回原标签页完成，不依赖卡网自动跳转。卡网若只把兑换网址显示成纯文本，需复制完整网址到浏览器打开；这一步不能宣传为免复制。注册、两步验证、Passkey、第三方登录和切换账号共用原有账号体系。

## 后台分别设置六档链接

入口：**系统设置 → 计费与支付 → 充值档位链接**，页面路径为 `/system-settings/billing/purchase-links`。

六个输入框分别对应 10、20、50、100、200、其他，点击“保存更改”后一起保存到 `payment_setting.purchase_links`：

```json
{
  "10": "https://商户网站/10档商品",
  "20": "https://商户网站/20档商品",
  "50": "https://商户网站/50档商品",
  "100": "https://商户网站/100档商品",
  "200": "https://商户网站/200档商品",
  "other": "https://商户网站/其他商品"
}
```

- 每档独立保存，留空则前台该档暂不可购买。服务端只接受这六个键和有效的 `http/https` 链接；不允许脚本链接或带账号密码的链接。
- 原 `TopUpLink` 仅在新配置尚未出现 `other` 键时作为“其他”档的兼容入口；在新页面保存“其他”为空后，不会再回退到旧链接。
- `/api/user/topup/info` 增加 `purchase_links`，始终提供六个键，未配置的值为空。原在线支付的 `amount_options`、折扣、支付网关和计费逻辑不变。
- 六档的真实商品网址由运营填写，不会把同一个网址自动套到所有档位。当前已知卡网商品地址为 <https://catfk.com/item/fn2e05>，其余档位的实际网址尚未提供。
- 返回提示只存放档位、账号 ID、随机标识和时间；不存放兑换码，也不读取卡网订单。新弹窗提交时带 `expected_user_id`，若浏览器登录账号已切换，服务端拒绝兑换，避免将积分充入另一个账号。

## 给卡网准备发货内容

1. 在本站“兑换码”管理中生成相应额度的兑换码。商品和面额文案使用“积分”，例如“10元积分”。
2. 勾选需要上架的兑换码，点击“复制有效兑换链接”，每行对应一条卡密；已使用、停用或过期的码会自动排除，按钮显示可导出的数量。单条兑换码的操作菜单也可以复制兑换链接。
3. 将复制的链接逐行导入卡网库存，作为实际发货内容。每个兑换码只导入一次。
4. 将对应商品网址填写到后台“充值档位链接”的相应档位。可在卡网商品说明中填写：“购买后回到 GHLINK，在兑换窗口粘贴收到的兑换码；若收到兑换链接，也可直接打开后核对账号并确认兑换。”

链接格式：

```text
https://ghlink.top/redeem#code=对应的本站兑换码
```

卡网无需新增支付回调或获取本站后台密钥。上线前需在商户后台确认库存允许导入完整网址，并预览发货内容是否可点击；尚未确认前，保留纯兑换码发货和钱包手动兑换作为可用路径。本站改动不会自动上传或替换卡网库存。

原先已经发出去的纯兑换码仍可在钱包手动兑换。链接和原兑换码共用同一份使用状态，任意一种方式兑换成功后，另一种方式也不能重复入账。

## 页面与状态

- 打开链接不会兑换：只建立有效期为 30 分钟的待兑换状态，兑换码本身的到期时间不变。超时后重新打开原链接即可继续。
- 钱包先读取真实额度，再显示“兑换码已识别”、积分、当前账号和“确认兑换”。不会根据商品标题猜测面额或货币换算。
- 点击“切换账号”保留待兑换内容；退出并登录另一个账号后重新核对。
- 点击确认后，服务端同时核对登录账号与本次待兑换状态，调用现有事务完成兑换，更新余额并显示成功状态。
- 兑换码无效、已使用、停用或过期时显示具体原因。后台未启用兑换功能时沿用现有的限制。
- 点击“稍后兑换”或关闭弹窗取消本次待兑换状态；之后可以重新打开原链接。

链接中的兑换码只在最初的网址片段中出现，不放入登录跳转参数或浏览器存储。后续待兑换信息由加密的 HttpOnly Cookie 承载，页面只拿到额度和用于确认的状态标识。兑换链接应按原卡密保管。

## 接口

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `POST /api/user/topup/link` | 无需登录，限流 | 接收 `{ "key": "兑换码" }`，建立待兑换状态，不改变余额 |
| `GET /api/user/topup/link` | 已登录，限流 | 返回 `quota`、`user_id`、`intent_id`，不消耗兑换码 |
| `POST /api/user/topup/link/redeem` | 已登录，限流 | 提交预览返回的 `user_id` 和 `intent_id`，核对后完成兑换 |
| `DELETE /api/user/topup/link` | 已登录 | 清除本次待兑换状态 |

未修改兑换码额度计算、定价、支付方式或原有手动兑换接口。
