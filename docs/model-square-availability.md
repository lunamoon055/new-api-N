# 模型广场对外展示状态

管理员可在模型卡片、表格状态列或详情页，通过“对外展示”开关为单个模型设置“可用 / 不可用”。访客与普通用户只看到状态。默认显示“可用”；设置“不可用”后，模型仍保留在模型广场，方便查看信息及恢复展示状态。

该功能只控制展示文案，不改变渠道、模型元数据启用状态、计费、令牌权限或实际请求路由。状态按完整的公开模型 ID 独立保存，同一模型的多个分组共用状态；不同公开别名分别设置。上游模型同步及备注编辑不会覆盖此设置。

## 接口与持久化

- `PUT /api/models/display-status`：继承模型管理路由的 `AdminAuth`，管理员及超级管理员可操作。
- 请求体：`{"model_name":"dola2.5","available":false}`。`available` 必须显式提供布尔值；缺失、null、字符串或数字均返回 400。模型必须已列入模型广场。
- 成功返回：`{"success":true,"data":{"model_name":"dola2.5","available":false,"updated_time":1793059200}}`（时间为示例）。
- `GET /api/pricing`：每个模型增加布尔字段 `display_available`，无手动设置时为 true。响应禁止 HTTP 缓存；保存后当前页面立即刷新，其他打开的模型广场每 30 秒刷新。
- `model_display_statuses` 独立存储展示状态，通过 GORM upsert 写入，避免 false 被零值更新规则忽略；常规迁移和快速迁移均包含新表。使用 SQLite、MySQL、PostgreSQL 通用的表结构与 GORM 操作。

已覆盖访客与普通用户写入拒绝、管理员及超级管理员写入、参数校验、反复开关及缓存刷新后持久化、只修改目标模型、模型元数据和渠道能力保持原样，以及 `/v1/models` 发现结果不受展示状态影响。

本地 PostgreSQL 已完成新表迁移；浏览器验证了管理员关停/恢复、刷新后状态保留、未登录访客只读展示、卡片/表格/详情一致。测试模型已恢复到测试前状态。前端类型检查、相关 ESLint、i18n 同步和生产构建通过。MySQL 未连接实测；未提交、推送或部署线上。
