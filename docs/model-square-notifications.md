# 模型广场通知提醒规则

- 新公告发布后的 24 小时内，用户进入模型广场、重新点击模型广场、回到浏览器窗口或恢复网络时检查通知。
- 页面保持打开且可见时，每 15 秒检查一次；其他设备发布的通知也通过此检查发现。
- 本浏览器后台发布成功后发送不含通知内容的刷新信号，让其他标签页及时重新拉取。
- 已发布且未读的站点公告和时间线通知合并为一批展示；未来发布、刚满 24 小时、无有效日期的历史内容不触发自动弹窗。
- 窗口正在显示某批通知时，内容固定。之后发布的新通知不会被替换进当前窗口，也不会被此次关闭误标为已读。
- “关闭”和“今日关闭”只确认当前这批通知的版本，之后新发布或修改的版本仍会提醒。同一版本已读后不会反复提醒。
- 管理员、普通账号、不同账号和访客各自保存状态；同浏览器的多个标签页合并已读记录。
- 拉取失败不会因后台通知请求而退出账号或跳到全站错误页。断网、页面不可见时不根据过期缓存新开弹窗。网络恢复、返回页面或下一轮检查会重试。
- 其他弹窗正在打开时，新通知保留为未读，稍后重试，避免打断模型详情等操作。
- 浏览器禁止或无法写入本地存储时，当前页面仍可正常确认通知；浏览器拒绝持久化时，重开页面可能再次提醒。
- 普通小喇叭仍可手动查看已发布历史通知。自动提醒只显示最近的未读内容。

## 接口与兼容性

`GET /api/notifications` 为公开只读接口，提供站点公告、时间线通知和服务端毫秒时间，响应禁止 HTTP 缓存。自动提醒窗口按服务端时间判断 24 小时，避免依赖用户电脑的时钟。

原有 `/api/notice` 和 `/api/status` 保持兼容。站点公告内容变更时记录发布时间；仅保存相同内容不会重新计时。时间线按后台填写的发布时间判断。

旧版不区分账号的全局已读状态不会归到当前账号。旧版“当天全部关闭”的标记不会继续屏蔽新通知；能够归属账号的历史已读版本保留。

## 回归范围

自动化用例覆盖 24 小时临界值、未来发布时间、历史缺失日期、编辑/复用 ID、站点公告版本、批量条数、弹窗快照、普通关闭后再发布、今日关闭后再发布、弹窗打开期间发布、刷新与跨天、账号隔离、标签页合并、存储故障和旧数据迁移。公开接口覆盖访客、普通用户、管理员及超级管理员。

浏览器流程另验收：进入页面、停留时发布新通知、关闭旧批次后收到新批次、今日关闭后发布、弹窗期间到达新通知、重新点击导航、跨标签页发布、网络失败后恢复。
