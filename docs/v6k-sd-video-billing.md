# V6K SD2.0 / SD2.5 分辨率与参考视频计费

核对日期：2026-11-13。来源：[统一视频文档](https://www.v6k.top/docs?guide=unified&category=video)、[公开价格目录](https://www.v6k.top/api/pricing)、[视频 OpenAPI](https://www.v6k.top/docs/openapi-video.json)。原始价格表达式、能力备注和增量配置保存在 [v6k-sd-models-2026-11-13.json](./v6k-sd-models-2026-11-13.json)。

## 公开 ID 与接口

| 本站公开 ID | V6K 上游 ID | 分辨率 | 图片 / 音频 / 视频 |
| --- | --- | --- | --- |
| `Seedance2.0:(无视频参考)` | `SD2.0` | 480p、720p、1080p、4K | 9 / 3 / 3 |
| `Seedance2.5:(无视频参考)` | `SD2.5` | 480p、720p、1080p | 30 / 10 / 本站最多 10 段 |

公开 ID 沿用已有配置，名称中的“无视频参考”表示基础价格不含参考视频。现在可以携带参考视频并单独付费，不需要下游更换模型名称或接口。SD2.5 的上游视频数量上限未公布，10 段是本站中转上限；本站按运营方 2026-11-13 确认的范围统一配置：SD2.0 为 5–15 秒，SD2.5 为 5–30 秒（均为连续整数秒）。模型广场保留本站视频参考上限，不展示上游数量尚未公布的提示。比例沿用本站八种缺省选项。

创建使用 `POST /v1/videos`，查询使用 `GET /v1/videos/{task_id}`，下载使用 `GET /v1/videos/{task_id}/content`。对外字段保持 `duration`、`ratio`、`resolution`、`referenceImages`、`referenceAudios`、`referenceVideos`；同时兼容已有的 `seconds`、`images`、`audios`、`videos`。适配器发送上游 ID 及上游要求的字段。`duration` 和 `resolution` 必须明确提交。

```json
{
  "model": "Seedance2.5:(无视频参考)",
  "prompt": "参考视频中的镜头运动，拍摄阳光下的森林",
  "duration": 5,
  "ratio": "16:9",
  "resolution": "720p",
  "referenceVideos": ["https://cdn.example.com/reference.mp4"]
}
```

## 价格档位

本站沿用 USD 计费，不修改其他模型价格、分组倍率或全局汇率。下表人民币对照使用上游 USD/CNY=7.3，不能用它替代本站当前汇率设置。初始生成单价和参考视频单价相同，但后台可分别调整。

| 模型 | 分辨率 | 生成 USD / 秒 | 参考 USD / 输入秒 | 上游人民币对照，两种单价均为 |
| --- | --- | ---: | ---: | ---: |
| SD2.0 | 480p | 0.013698630137 | 0.013698630137 | ¥0.10 / 秒 |
| SD2.0 | 720p | 0.021917808219 | 0.021917808219 | ¥0.16 / 秒 |
| SD2.0 | 1080p | 0.047945205479 | 0.047945205479 | ¥0.35 / 秒 |
| SD2.0 | 4K | 0.123287671233 | 0.123287671233 | ¥0.90 / 秒 |
| SD2.5 | 480p | 0.024657534247 | 0.024657534247 | ¥0.18 / 秒 |
| SD2.5 | 720p | 0.041095890411 | 0.041095890411 | ¥0.30 / 秒 |
| SD2.5 | 1080p | 0.095890410959 | 0.095890410959 | ¥0.70 / 秒 |

SD2.0 的备注曾写 480p=0.08、720p=0.10，与正式表达式及详情表冲突，本次采用正式表达式。SD2.5 表达式包含 4K 零价兜底，但备注未确认支持 4K，本站不开放这个档位，也不作为免费生成。

```text
费用 = (生成秒数 × 对应分辨率生成单价
      + 所有参考视频的实际总秒数 × 对应分辨率参考单价) × 分组倍率
```

参考价格依据请求的输出分辨率，不依据各段输入视频分辨率。没有参考视频时附加费为零。例如 SD2.5 的 720p 生成 5 秒，携带 2.5 秒和 5 秒两段参考视频，分组倍率 1：费用为 `(5+2.5+5) × 0.041095890411 = USD 0.5136986301375`，约 ¥3.75。本站额度按合计金额向上取整一次，不逐段取整；上游是否采用同样的秒数取整策略未公布。

## 后台配置与下游读取

后台“系统设置 → 计费设置 → 模型价格”的分辨率按秒计费中，每档分别填写生成单价和“参考视频每秒单价”。参考单价留空为未配置，有参考视频时拦截请求；显式填写 `0` 才表示该档参考视频免费。定价按本站公开模型 ID 保存，原始模型名、映射别名、自定义模型和暂未绑定渠道的模型均可保存；不要求预先添加 V6K 渠道、填写映射或命中特定上游型号。保存整张价格表时，其他模型缺少或移除了映射也不会阻断保存。

V6K 实际请求按公开模型 ID 读取价格。有参考视频价格配置的模型会启用时长核验与附加费，未映射时原样发送模型 ID，已映射时发送映射结果；计费始终使用公开 ID 的价格。SD2.0 / SD2.5 继续使用已核对的能力和价格校验。其他旧模型没有显式参考价格配置时沿用原处理，不新增下载或附加费。价格保存不自动添加、删除或猜测模型映射，也不改变其他渠道适配器的素材协议。

三个定价配置通过 `billing_setting.video_pricing_config` 一起保存，数据库事务成功后统一更新运行配置，失败不发布部分价格。持久化仍使用 `billing_setting.video_billing_mode`、`billing_setting.video_resolution_prices`、`billing_setting.video_reference_prices` 三个选项，兼容原有读取方式。基础 `ModelPrice` 保留 720p 单价供旧客户端识别，实际请求以分辨率档位为准。

`GET /v1/pricing`（本站 API Key）和模型广场目录返回 `video_billing_mode: "tiered_seconds"`、`video_resolution_prices`、`video_reference_prices`。下游必须将生成费和参考费相加；`model_price` 不能代表整条视频价格。`/v1/pricing` 的 `price_scope=base` 表示基础价，两组单价已按请求币种换算，使用对应 `group_ratio` 乘一次。模型广场按分组展示和创作目录中的分组价则已乘倍率，不要重复叠加。能力参数同时返回 `reference_video_billed_per_second: true`。

## 计量、提交与结算

- 本站读取参考视频实际文件，核验 MP4 / WebM 容器的时长元数据；不采用客户端 `duration_seconds` 或自填计费字段。缺少有效时长、网页、空文件和异常容器会在预扣与上游提交前拒绝。
- URL 下载沿用 SSRF、DNS 和逐跳重定向检查，不向素材站发送本站或上游密钥、Cookie。经核验的 URL 文件字节直接转为上游 multipart `video`，避免上游再次读取已改变的 URL；用户直接上传的文件也执行相同计量。
- 本站中转限制：单段 32 MiB、总计 96 MiB，整批核验 45 秒，最多同时核验两批；每段可计量时长不超过 3600 秒。这些是本站资源限制，并非上游承诺的模型能力。其他未配置参考单价的旧模型继续走原协议。
- 校验成功后，将分辨率、生成秒数、参考总秒数、两种单价与分组倍率保存为任务快照，再走现有余额 / 令牌预扣链路。后续改价不追溯已提交任务。
- 一个请求只提交一次上游创建 POST，不因网络错误或参数失败重复创建。成功按快照结算；明确失败按现有任务状态事务完整退款，重复轮询只退款一次；未知状态继续查询。
- 消费和退款记录包含 `video_reference_billing` 的详细计量快照。参考视频收费不使用 token 表达式，也不重复套用旧的输出时长倍率。
