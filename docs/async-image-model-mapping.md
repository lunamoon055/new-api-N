# 异步图片模型映射（管理员维护说明）

公开模型名与真实上游型号是两个独立字段。渠道映射只改变新任务实际提交的上游型号，不改写公开模型名、计费归属或已有任务的型号快照。

## 配置边界

- 下游仍提交公开模型 ID；在对应渠道的模型映射中配置真实上游型号。
- 根据《图片模式调用示例.md》，上游列出的型号为 `gpt-image-2`、`gpt-image-2.5`、`nano-banana-pro`、`nano-banana2`、`seedream-5-0`。
- 用户补充确认 `gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst` 也是真实上游型号，接口和参数规则与 `gpt-image-2` 相同。两者复用其能力规则，但未配置映射时仍原样发送自己的型号，不自动替换成 `gpt-image-2` 或 `gpt-image-2.5`。
- 本次提前解析映射仅作用于 LinkSky 渠道的 `/v1/images/async-generations` 提交链路，不改变其他渠道同名模型的协议，也不自动回退同步接口。

## 请求与任务行为

1. 选择渠道，解析该渠道的模型映射（支持现有链式映射规则）。
2. 按映射目标校验分辨率、比例和参考图数量，再提交异步任务；未知目标和循环映射在提交前报错。
3. 公开名保留在请求和计费上下文中，上游请求体只发送真实型号。
4. 保存任务创建时的公开名、上游型号、接口和任务 ID；后续查询复用这些快照，不使用新的模型映射重新生成。

映射到另一个模型可能改变新任务可用的分辨率和比例，管理员仍需同步配置面向用户的能力与定价。任意无效映射不能保证生成成功。

## 验证

相关回归测试覆盖全部七个目标型号、中文公开别名、flare/sunburst 原名及映射、链式映射、重试重置、按目标校验能力，以及已有任务查询快照。测试不调用外部图片生成服务。

```sh
go test ./relay/channel/task/sora ./relay ./middleware ./controller ./service
```

代码修改需要部署到网关后才生效；渠道映射需另外配置，不能以本地测试通过代替线上生成验收。
